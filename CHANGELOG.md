# Changelog

Each release's notes. From 1.0.0 on, a major or minor release has hand-written notes under `docs/releases/`, and the release workflow uses them as the release body. Older releases list their commits on GitHub.

## Unreleased

- The self-test of `scripts/ci/check-images.sh` copies the whole tree again once the list of tracked paths passes 128 KiB. It piped that list through `xargs` to `tar`, and GNU `xargs` split a list that long over two `tar` runs; the reading `tar` stopped after the first archive, so Guard's `images` job failed on a broken pipe (exit 123). One `tar` now reads the list itself (`tar --null -T -`). Nothing the check reports changes.
- `og report render --summary summary.json -o REPORT.txt -o REPORT.html` writes the frame of both reports in Rust: the chapters and their contents, each section's frame with its step, state, file date and "New since" badge, the caveats under each card title, the run facts with the OwnGenome release and the database re-check, what the report leaves out, the CSS and the HTML escaping. It writes the quality-control and variant sections so far and leaves the others out. No step calls it yet: `bin/render_report.py` still writes both reports, so nothing a run writes changes. On 99 summaries (those of the 71 summary-collect parity cases and 28 changes of one of them) its output is byte for byte the Python's for those parts. What it does on purpose that the Python did not:
  - A section whose data lacks a field the report reads, or has one of the wrong kind, reads as could not be read and shows as failed in the HTML contents and its badge, and the rest of the report is written. The Python stopped with a KeyError and wrote no report.
  - A variant count that is text is escaped in the HTML card; the Python put it into the page as it was.
  - Each report is written under a temporary name of its own and renamed into place.
  - An `-o` name must end in `.txt` or `.html`, or the verb exits 2 and writes nothing. The Python wrote the HTML report for any name that did not end in `.txt`.
  - A summary with no section for a step reads that section as not run. The Python stopped with a KeyError when the `variants` section was absent.

A new `roh.data.scope` records the chromosomes, denominator and scope source. Relationship labels and UPD flags require sites on all 22 autosomes and the full unmasked autosome length. Segment-only files use their observed chromosomes as an unverified lower bound and get neither label. Empty input has null F_ROH. Segment counts and the step 11 summary table keep their format.
- A one-chromosome ROH flag now names regions and citations without syndrome names. Its note includes deletion, acquired loss of heterozygosity and shared ancestry as alternatives. The maternal and paternal JSON keys remain as `"-"` for reader compatibility. The attributed `assets/imprinted_regions.tsv` is embedded at build time, replacing the duplicated Rust table. The container builder mounts it, and the source stamp includes its blob hash, so a table edit makes an old binary stale. The stamp format and `tree-hash` command name stay the same. Every listed chromosome uses the same lookup, including chr11 and chr15. A region hint does not establish overlap with its imprinted locus or parental origin. Broad cytoband names remain reference labels, not diagnostic intervals.

- Step 23's ClinVar tier now holds only the allele ClinVar classified. It took every VEP record at a step 6 hit's position, so when a call of T>A,C split into two records and ClinVar classified only T>A, the T>C record also landed in `clinical/<sample>_clinvar_pathogenic.vcf.gz`, in the tier's count and, when no other tier kept it, in `_clinical.vcf.gz` and `_clinical_summary.tsv` with `FREQ_TIER` read as a ClinVar record. The tier now matches CHROM, POS, REF and ALT. - A heteroplasmic MT-RNR1 variant now gives the aminoglycoside warning. Step 07 and the Nextflow PHARMCAT process passed a named MT-RNR1 allele to PharmCAT only at an allele fraction (AF) of 0.95 or more, so m.1555A>G or m.1494C>T at AF 0.05 to 0.95 left MT-RNR1 No Result and the warning was lost. CPIC sets no heteroplasmy level at which aminoglycosides are safe, so `og pgx mito-merge` now passes a PASS named allele from AF 0.05, the pipeline's heteroplasmy floor, and its log says `heteroplasmic` with the AF. Below AF 0.05 the allele is not passed, the log says it is below the detection floor, and the gene is not called Reference either; beside a named allele at the floor it is only named in the log and does not withhold that call. The default of `--min-af` moves from 0.95 to 0.05; the option stays. A named allele whose AF reads `nan` is now held back as having no allele fraction; it was passed as homoplasmic. No output file or format changes: the MT-RNR1 line of the outside calls now appears in these cases. Part of #411 (pgx-04, pgx-32).

- `run-all.sh` now sizes Nextflow from the container engine, not only from the host. Docker Desktop and colima run the containers in a VM that is usually smaller than the Mac, but `run-all.sh` gave Nextflow the Mac's CPUs and RAM. Nextflow then started more tasks than the VM could hold, and the VM killed them (exit 137). When `docker info` reports fewer CPUs or less memory than the host, `run-all.sh` now passes the engine's figures as the default `--max_cpus` and `--max_memory`. It also writes them to `<sample>/nextflow/executor.config` and passes that file with `-c`, so Nextflow books no more than the VM has. A `-c` of your own comes after it, so each `executor` setting in it wins. `THREADS`, `--max_cpus` or `--max_memory` of your own still cap each task, and `executor.config` never books less than them, so Nextflow does not refuse a task that asks for more than the VM's figure. On native Linux the engine reports the host's figures, and the command is unchanged. `validate-setup.sh` adds an `[INFO]` line when Docker has less memory than the host. No option or output file changes.
- `benchmark-variants.sh` now compares genotypes, not just alleles, between callers. Its pairwise mode counted a site as shared when both callers had the same allele there, so a site one caller called 0/1 and the other 1/1 still scored as full agreement, and the summary said a Jaccard index of 1.0 meant perfect agreement. `comparison.tsv` gains two columns at the end, `GT_Concordant` and `GT_Concordance`: the shared sites whose genotypes also agree, ignoring phase and allele order, with a homozygous call equal to its haploid form; a site with no genotype on either side is not a match. The existing columns are unchanged.
  - The step now also compares Clair3 (`vcf_clair3/`) and `<sample>.vcf.gz` in any other `vcf_*/` directory. `run-all.sh` with `BENCHMARK=true` already queued the step for those directories, and the step then found one caller and exited 1, so the run reported a failure; step 03e also told long-read users to run it.
  - The docs stop calling step 03a the clinical-lab standard without a caveat: it runs HaplotypeCaller without base quality score recalibration (BQSR) and with `-ERC NONE`, so it is not the full GATK Best Practices workflow. Part of #411 (plat-55, plat-71).

- The always-report list of step 06 (`clinvar/<sample>_clinvar_deep_intronic.tsv`) now says what each call really is. A `0/0` with a filter such as `LowQual`, a `0/0` without a GQ, and a `0/0` read from one or two reads all read as plain `ref`, and a male's one-copy chrX call (`1` or `0`, as some callers write it) read as the raw `1` or as no call.
