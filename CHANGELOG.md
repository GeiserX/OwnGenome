# Changelog

## Unreleased

- The STRchive catalog, Exomiser's zips and the genetic map are now set up by the Rust `og` binary: `og str catalog` (replaces `bin/strchive_convert.py`, which is gone), `og setup unzip` and `og setup genetic-map` (replace two Python programs inside `scripts/setup.sh`). The catalog and its ranges table are the same, byte for byte, and so are the unpacked Exomiser data and the maps. `setup.sh` builds `og` first when these need it. The STRchive catalog is converted once more after this update, because its stamp now names the converter's format instead of the Python file's hash.
  - Steps 26b and 51: each genetic map file is written whole or not at all. Before, a setup killed while it wrote a map could leave a truncated `.rfmix.map` that every later setup took as done. Step 26b's maps now carry a stamp, `maps/DONE`, written last; an install without it writes every map again once.
  - `setup.sh --exomiser-data`: a zip member whose name leaves the folder (an absolute path or `..`) is refused, and nothing is unpacked. Python's `extractall` wrote it elsewhere, under a name with those parts dropped.
  - A genetic map row with fewer than four fields, a STRchive record with a missing coordinate, and a locus structure with no repeat now stop with exit 2 and a message, not a Python traceback.

- Four VCF filters of steps 04, 05 and 07 now run in the Rust `og` binary: `og sv inv-filter` (step 04), `og sv svlen-fix` (step 05), `og pgx refblock-fill` and `og pgx mito-merge` (step 07). They replace `bin/manta_inv_filter.py`, `bin/sv_svlen_fix.py`, `bin/pgx_refblock_fill.py` and `bin/pgx_mito_merge.py`, which are gone. Their output is the same, byte for byte, except for these fixes. Steps 04, 05 and 07 now need `og`: `scripts/setup.sh <genome_dir>` builds it, and `scripts/setup.sh --og` builds only it.
  - Step 05: an SV record whose INFO held `SVLEN` or `END` twice kept the old last value beside the new one. The rewrite now replaces the item it read.
  - Step 07: where the gVCF had a record at a multi-base PharmCAT position that was not a reference block, the input got that record and a 0/0 record at the same position. The gVCF's record is kept, the 0/0 record is dropped, and the log says so, whether the gVCF's reference block at that position comes before or after the record.
  - Step 07: two PharmCAT positions that start at the same base shared one coverage count, so the shorter one could be filled or refused on the longer one's bases. Each position now has its own. PharmCAT 3.4.0 has no such pair, so its results do not change.
  - Step 07: a 0/0 record after a gVCF line without a final newline was glued onto that line.
  - Step 07: a multi-base change of one length at an MT-RNR1 position was logged as "an insertion or deletion". It now reads "a multi-base change". Nothing else changes: no MT-RNR1 call is passed.
  - Step 07: `--min-depth 0` with a named MT-RNR1 position missing from the depth file crashed. That position now counts as depth 0.
  - Malformed input to any of the four (a record with too few columns, a `POS` that is not a whole number) now stops with exit 2 and a message that names the file and line, not a Python traceback.

- The CYP2D6 depth check and the RFC1 motif count, ported to the Rust `og` binary: `og pgx cyp2d6-bed`, `og pgx cyp2d6-measure` and `og pgx cyp2d6-check` (from `bin/cyp2d6_depth_check.py`) and `og str motif` (from `bin/rfc1_motif.py`) read BAMs with htslib, without pysam. On 67 cases they write what the Python writes, byte for byte, with one fix: a mosdepth regions file that lists one region twice with two depths is now refused (exit 2); the Python averaged the two. Steps 21, 32 and 9b still run the Python for now; no option, output file or format changes.
- Genome map, first pieces, in the Rust `og` binary. `og map build` writes one person's map document: the chromosome bands, the runs of homozygosity, and every finding with a place on the genome (its own position, or its gene's span). A result the page keeps closed (a finding to act on, and APOE on every page) is tagged with its id on every row that could reveal it, so the page's own closed-result rule hides those rows too. `og map genes` builds the gene and exon files once per GENCODE release, offline. No pipeline output, option or page changes yet; the live page starts drawing the map in a later change. The format is in `rust/crates/og-map/README.md`.
- Rust building blocks for the ports that look things up by position. `og-io` reads the lines of a region from a bgzipped file through its `.tbi` or `.csi` index, as `tabix` prints them, reading only the blocks the index points at. `og-intervals` reads bases from an uncompressed FASTA through its `.fai`, as `samtools faidx` prints them, and refuses a compressed FASTA or a `.fai` that does not match the file. It also adds sorted interval sets (union, intersection, lookups by binary search, BED files such as the PAR regions) and reciprocal overlap. Nothing calls them yet, so no pipeline output, option or file changes.
