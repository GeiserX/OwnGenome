# Changelog

Each release's notes. From 1.0.0 on, a major or minor release has hand-written notes under `docs/releases/`, and the release workflow uses them as the release body. Older releases list their commits on GitHub.

## Unreleased

- og now runs eight of setup's installers itself, one flag at a time, and `scripts/setup.sh` hands those flags to it: `--sample-qc-data`, `--viral-data`, `--kir-data`, `--chip-data`, `--cnvpytor-data`, `--somatic-data`, `--prs-academic` and `--pull-only`. Each one downloads, checks, writes and prints what the bash installer did, with the same exit code. `og setup install` takes the same arguments as `setup.sh`. A flag og has not ported yet goes back to `setup.sh`, so every flag and variable keeps working. `OG_SETUP=bash` keeps every installer in bash, for a comparison or a way back. `og setup ported FLAG` and `og setup flags --long` say who runs each flag. Setup still takes one flag per run. For the flags og runs now, a second flag after the first (`setup.sh --kir-data DIR --viral-data`) used to be ignored and is now refused with exit 2; the others follow as they move. `--pull-only` needs og now, as every other flag already did. An installer whose lock folder cannot be made (a folder you may not write into) now stops at once with `ERROR: cannot create the lock ...` and exit 1; bash waits for it forever. Ctrl-C, a kill or a closed terminal removes the lock and exits 130, 143 or 129, as bash does; a signal ignored when setup started (`nohup`) stays ignored. `og dev everything-check` now also fails when `setup.sh` and og's setup table do not list the same flags.
- A new check compares two setup installs file by file, so the move of `scripts/setup.sh` to Rust cannot change what gets installed unnoticed. `og dev install-manifest` lists an install tree with each file's size, sha256 and permission bits, and compares two such lists. A file whose bytes change from run to run is compared by its kind: gzip content and container (BGZF or plain gzip), VCF with the dates masked, an index by its names, record counts and fit to the data, jellyfish counts with the host, folder and time of the header masked, or numbers rounded to 4 significant digits. Stamps are always compared byte for byte, and logs for their presence only. `tests/setup/ab.sh` installs one component with bash and with og and compares the trees, exit codes, logs, missing list, images, `NXF_HOME`, `bin/.og` and who owns what each side wrote, with a planted-byte control in a file the component wrote in every run; a side A that fails, or a run that installs nothing, is not green (`docs/testing.md`). Developer tooling only; nothing a user runs changes.
- A Locityper killed for memory (step 53) is now retried with twice the memory. The `LOCITYPER` task caught Locityper's exit code and wrote it into the table, so the task ended green and Nextflow never retried it: every locus read "not called". Now a kill (exit 137 or 143) on the first attempt ends the task with that code, and the retry writes the table, as before. `scripts/53-locityper.sh` has no retry engine, so it keeps writing the exit code into the table; its container already gets 16 GB. `tests/e2e/t3-run-fixes-1-memory-retry.sh` runs the module's real script with a stand-in Locityper that is killed once, every time, or never.
- CPSR (step 17) now asks for 16 GB, in the pipeline and in `scripts/17-cpsr.sh`. On a whole genome it was killed under process_medium's 8 GB, so every run paid a first attempt that could not finish, and on a host whose `--max_memory` is 8 GB both attempts died. Our end test had already measured a peak of 12.3-15.6 GB. `--max_memory` still caps the task; the same e2e case checks both the 16 GB and the cap. No other step's whole-genome peak in `docs/hardware-requirements.md` is above its request.
- `validate-setup.sh` now sees a resume whose work directory was given with `-w`. `run-all.sh` passes the work directory of its run (`-w`, `-work-dir`, `NXF_WORK`, or `<sample>/nextflow/work`) to it as `NXF_WORK`. A resume there is a warning under the 200 GB minimum, not a failure that stops the run. It counts as a resume only when the work directory holds tasks, the sample's `nextflow/` folder holds the Nextflow cache that `-resume` reads, and the sample's last Nextflow log (`nextflow/.nextflow.log`) names that work directory. So a work directory that other samples share is no resume of a fresh sample, nor of a sample that ran before in another work directory. When the work directory is on another disk, that disk's free space is checked too: under 200 GB it fails a fresh run. A disk with 0 GB free, either one, now fails too, also on a resume; the sample's disk at 0 GB used to pass with no line. `tests/fake-docker/t3-run-fixes-validate-work-dir.sh` covers both disks, a full disk on a resume, a shared work directory, a sample that ran before in another work directory, the same directory reached through a link, and `run-all.sh` with `-w` and with `NXF_WORK`.
- `CPSR` and `CNVPYTOR`, the two Nextflow tasks that run as root, now give their work files back to you when their script ends, also when it fails or one of its programs is killed for memory. Nextflow's `docker.fixOwnership` gives them back only after a task that succeeds, and with GNU `chown --from`, which the BusyBox `chown` of the biocontainers images refuses: CNVpytor's work files stayed root's even when it passed, and so did those of a CPSR attempt killed for memory. The same refusal prints a harmless BusyBox usage text at the top of `.command.err` in tasks that run as you; the troubleshooting guide now says so. `tests/e2e/t3-run-fixes-2-root-tasks-owner.sh` checks the work directories under the docker profile, with a root task with no give-back as the control.
- Setup now keeps every raw download and reuses what is already on disk, so a slow or rate-limited server is paid for once. Before, setup deleted the VEP, PCGR, AnnotSV, Exomiser, AADR, archaic, MoChA and other archives once they were installed, and read the ancestry and Locityper panels straight from the server without saving them. Some files already on disk were reused and others were downloaded again. Now every download goes through the new `og setup fetch`, and `assets/data-sources.tsv` lists every source setup downloads, with its path, URL, checksum, size and licence. The raw files stay in `<genome_dir>/downloads`, or in the folder `OG_DOWNLOADS` names, which several installs can share. A file already there that matches its pinned checksum is used with no download. When the checksum is a list on the server (VEP's `CHECKSUMS`, an md5 list), that small list is read first; the checksum that matched is saved beside the file (`<name>.checksum`), and when the list cannot be read a kept file that matches the saved checksum is used. A file with the wrong checksum is refused with a message that names the source, and it is never overwritten. A file you copy into the downloads folder under its name in the table is checked like a download. Locityper's panel region is saved there too, keyed by the panel URL and the regions. `og setup plan` lists, before any download, what the chosen options need, what is already there, the sizes, the raw files kept and the free disk, and `setup.sh` stops before the first download when the raw downloads it still needs do not fit. A download whose install is already done is not counted, so a rerun after `og setup prune` needs no extra space. An install that setup stamps counts as done only while its stamp names today's release, checksum and image; a rebuild that the archaic masks or table format, the fine panel's thinning or sample list, Locityper's loci or a regions setting forces is not counted; a folder of many files (the archaic genomes) counts as there only once its install is done, less the files it already holds. Keeping the raw files costs disk: about 69 GB for a plain setup and about 344 GB for `--everything`. `setup.sh --no-keep-downloads` (or `SETUP_KEEP_DOWNLOADS=false`) deletes each one once it is installed, as before, and `og setup prune` deletes the kept downloads later. The VEP and PCGR archives now live in the downloads folder, not in `vep_cache/` and `pcgr_data/`. A raw file or `.part` an older setup left at its old place (the VEP, PCGR, AnnotSV, Exomiser, Yleaf and pgsc_calc archives, the Parascopy, consumer-sites, AADR, MoChA, archaic, gnomAD-SV, MANE, HLA and GENCODE downloads, and the reference) is moved into the downloads folder before the fetch, which checks it there; when a copy is in both places, the one that passes its check stays, and with no check to say which, both stay. A download that matched its pinned checksum is kept when its unpack fails. Every download needs og, so `setup.sh` builds og before its first download and stops when it cannot; a step script that calls `fetch` needs `bin/og` as well. REVEL's and AlphaMissense's URL and sha256 move from `versions.env` to the table, and steps 17 and 25 read the PCGR and pgsc_calc URLs from it. Every `setup.sh` flag and variable keeps working. Reported by @larry0x in #633.

- The Nextflow pipeline runs exomes. It always called with DeepVariant's whole-genome model and measured coverage in 500 bp windows, so an exome came out with about 2x coverage and with the steps that need whole-genome depth reporting results from almost no reads. Two new options set it up: `--model_type WES` and `--capture_bed <the capture kit's BED>`. DeepVariant then runs its exome model on the capture regions, mosdepth reports the depth over them, and Manta runs with `--exome`. indexcov is skipped and the sex check comes from somalier, so `sample_qc` must be in `--tools`. CNVpytor, ROH, TelomereHunter, archaic, MoChA, viral, Cyrius, Parascopy, Locityper, MEI and the mtDNA copy number are not run, and the log says "not run: exome". The report's mean depth for an exome is the on-target one, mosdepth's `total_region` row, so the QC lines, the live page and the genome facts no longer read an exome as a 2x genome with every gene below the depth floor. The report takes that row when the run manifest records `model_type WES` (Nextflow's report writes it), or when the row is under half as long as the genome-wide `total` row: 500 bp windows cover the whole genome, a capture kit 1-3% of it. `run-all.sh` with `--model_type WES` records the steps an exome leaves out, and indexcov, as `skipped (not run: exome)` in `logs/run_status.tsv` instead of done, and for an exome `summary.json`'s coverage section adds `on_target: true` (a whole genome's is unchanged) and the genome facts say assay type `wes`. A capture BED whose contig names are not the reference's (`1` instead of `chr1`) stops the run before any task. `docs/wes-guide.md` shows the command. A whole-genome run (`--model_type WGS`, the default) gives the same outputs as before, but `-resume` of a run started before this release reruns DeepVariant and mosdepth (they take the capture BED as a new input) and the report.
